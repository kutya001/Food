## 1. Цели и архитектура Этапа 2

Для полноценной работы платформы на **GitHub Pages** без серверов создаётся автономный клиентский слой данных и управления состоянием, обеспечивающий полную имитацию серверной СУБД, связей между сущностями и бизнес-логики.

```
Food/
├── js/
│   ├── router.js                    # Hash-роутер с переключением экранов (#/showcase, #/business, ...)
│   ├── state/
│   │   ├── db.js                    # Клиентская СУБД (CRUD, транзакции, Pub/Sub, валидация)
│   │   ├── seed.js                  # Богатый демонстрационный датасет (сомы, техкарты, KBJU)
│   │   └── auth.js                  # Мультиролевая аутентификация и смена контекстов
│   └── services/
│       └── exportService.js         # Экспорт/импорт всей базы данных в JSON и сброс
```

## 2. Модель коллекций данных (`js/state/db.js`)

1. **`users`**: `id`, `name`, `email`, `phone`, `activeRole`, `roles` (`['client', 'business', 'pos', 'corporate', 'admin']`), `themePreference`.
2. **`establishments`**: `id`, `ownerId`, `name`, `type` (`canteen`, `fastfood`, `restaurant`), `address`, `rating`, `openHours`, `themeKey`.
3. **`organizations`**: `id`, `name`, `taxId`, `employeesCount`, `dailyBudgetPerPerson`, `address`, `contactPerson`.
4. **`warehouses`**: `id`, `estId`, `name`, `type` (`main`, `kitchen_prep`).
5. **`ingredients`**: `id`, `estId`, `name`, `category`, `unit` (`кг`, `л`, `шт`), `purchasePrice` (в сомах), `calories`, `protein`, `fat`, `carbs`, `allergens`, `stockQty`, `minStockQty`.
6. **`techCards`**: `id`, `estId`, `name`, `isSemiFinished`, `yieldNetto`, `items` `[{ingredientId, grossQty, lossPercent, netQty}]`, `calculatedCost`, `calculatedKbju`, `version`.
7. **`menuItems`**: `id`, `estId`, `techCardId`, `name`, `category`, `retailPrice`, `corpPrice`, `photoIcon`, `inStopList`, `dietary` (`['halal', 'vegan', 'gluten_free']`), `isDaily`.
8. **`orders`**: `id`, `userId`, `estId`, `type` (`b2c_retail`, `b2b_corporate`), `items` `[{menuItemId, name, qty, price, kbjuSnapshot}]`, `totalSum`, `paymentMethod`, `status`, `createdAt`.
9. **`posShifts`**: `id`, `estId`, `cashierName`, `openedAt`, `closedAt`, `cashRevenue`, `cardRevenue`, `totalRevenue`, `receiptsCount`, `status`.
10. **`corpRequests`**: `id`, `orgId`, `estId`, `targetDate`, `items` `[{menuItemId, portions, targetDept}]`, `totalSum`, `status`, `comments`.

## 3. Детальный состав работ

### Шаг 2.1: Клиентский движок базы данных (`js/state/db.js`)
* Реализация класса `Database` с хранением в `localStorage` под ключом `foodflow_db_v1`.
* Автоматическая инициализация сидовыми данными при первом открытии или повреждении данных.
* Универсальные методы:
  * `getCollection(name)`
  * `getById(name, id)`
  * `query(name, filterFn)`
  * `insert(name, record)`
  * `update(name, id, changes)`
  * `delete(name, id)`
  * `transaction(operationsFn)`
* Реактивная подписка на изменения (Pub/Sub):
  * `subscribe(collectionName, callback)` — для автоматического обновления представлений при изменении данных.

### Шаг 2.2: Реалистичный демонстрационный датасет (`js/state/seed.js`)
* **3 заведения общепита:**
  1. Столовая «Свежесть» (демократичные цены, комплексные обеды, супы, плов, салаты).
  2. Бургерная & Гриль «TaomGo» (стрит-фуд, бургеры, шашлык, фри, напитки).
  3. Ресторан высокой кухни «GastroHall» (премиум, стейки, морепродукты, десерты).
* **2 корпоративных заказчика:**
  1. ОсОО «Alfa Tech» (45 сотрудников, дневной лимит 350 сом).
  2. ОАО «Бишкек Финанс» (120 сотрудников, регулярные обеды).
* **30+ ингредиентов** с реальными закупочными ценами в сомах, КБЖУ и аллергенами.
* **15+ технологических карт** (с полуфабрикатами: «Бульон мясной», «Тесто дрожжевое», «Соус тар-тар», «Фарш говяжий»).
* **20+ готовых блюд** с диетическими тегами (*Халяль*, *Веган*, *Без глютена*).
* Начальные чеки кассы и история заказов.

### Шаг 2.3: Менеджер мультиролевой аутентификации (`js/state/auth.js`)
* Профиль текущего пользователя (`currentUser`).
* Быстрое переключение ролей (`switchRole(roleKey)`):
  * Автоматическая смена активного заведения (для владельца общепита) или организации (для корпоративного заказчика).
  * Автоматическая адаптация дефолтной темы оформления через `ThemeManager.applyRoleDefaultTheme(roleKey)`.
  * Уведомление через `showToast`.

### Шаг 2.4: Сервис экспорта, импорта и сброса данных (`js/services/exportService.js`)
* Метод `exportDB()`: формирует файл `foodflow_backup_YYYY-MM-DD.json` и инициирует скачивание в браузере.
* Метод `importDB(fileContent)`: проверяет целостность структуры JSON, валидирует коллекции и восстанавливает базу данных.
* Метод `resetDB()`: мгновенный сброс состояния к исходному демо-датасету.

### Шаг 2.5: Hash-роутер SPA (`js/router.js`)
* Поддержка маршрутов:
  * `#/showcase` — Витрина каталога блюд
  * `#/business` — Кабинет общепита (склад, техкарты, меню, финансы)
  * `#/pos` — POS-терминал кассира
  * `#/corporate` — Кабинет организации-заказчика (B2B заявки)
  * `#/admin` — Панель управления платформой
  * `#/profile` — Профиль и аналитика КБЖУ
* Подсветка активной ссылки в шапке при смене маршрута.
* Защита роутов по правам доступа (с подсказкой переключить роль).
