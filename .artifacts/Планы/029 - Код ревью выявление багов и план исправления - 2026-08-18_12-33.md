# План № 029: План устранения выявленных дефектов и нелогичных моментов по результатам глубокого код-ревью

**Дата и время:** 2026-08-18 12:33

---

## 1. Реестр выявленных багов и дефектов бизнес-логики:

| № | Уровень | Модуль / Файл | Выявленный дефект / Нелогичное поведение | Необходимое исправление |
| :---: | :---: | :--- | :--- | :--- |
| **1** | **Критично** | `js/components/userNutritionModal.js` | Дневник КБЖУ проверял несуществующее прямое свойство `dish.kbju`, из-за чего нутриенты в аналитике пользователя обнулялись. | Использовать сквозной резолвер КБЖУ: `item.kbju ?? tc.calculatedKbju ?? CalculationService.calculateTechCard(tc).kbju`. |
| **2** | **Критично** | `js/services/calculationService.js` | В строке 55 расчет КБЖУ требовал объект `ing.kbjuPer100g` и игнорировал прямые свойства `ing.calories`, `ing.protein`, `ing.fat`, `ing.carbs`. | Использовать безопасный доступ: `ing.kbjuPer100g?.calories ?? ing.calories ?? 0` для всех 4 нутриентов. |
| **3** | **Критично** | `js/components/checkoutModal.js` | При оформлении B2C-заказов в онлайн-витрине отсутствовало списание сырья со склада заведения. | Добавить вызов `StockService.deductStockForOrder(items, newOrder.estId)` при оформлении заказа. |
| **4** | **Важно** | `js/components/posPaymentModal.js` | При выборе метода оплаты «Корп. счёт» в POS-кассе сумма чека не списывалась с баланса организации `organizations`. | Добавить списание `currentBalance` организации при оплате чека кассиром по безналичному корп. договору. |
| **5** | **Важно** | `js/services/financeService.js` | В P&L отчете корпоративная выручка фильтровалась по старому статусу `in_progress` вместо `accepted`, `cooking`, `ready`, `on_way`, `delivered`. | Синхронизировать статусы B2B-заявок для точного расчета выручки и Food Cost. |
| **6** | **Важно** | `receiptModal.js`, `writeOffModal.js`, `stockService.js` | При операциях склада обновлялось только `currentStock`, а `stockQty` оставалось рассинхронизированным. | Обновлять оба свойства одновременно: `currentStock: newStock, stockQty: newStock`. |
| **7** | **Улучшение** | `js/services/calculationService.js` | Защита от деления на 0 при вычислении коэффициента выхода полуфабрикатов. | Защитить делитель: `Math.max(1, semiCard.outputWeight || 100)`. |

---

## 2. Пошаговый план устранения:

1. **Исправление расчетного движка `CalculationService`:**
   * Обновить получение КБЖУ сырья из прямых и вложенных свойств ингредиента.
   * Обеспечить защиту от деления на 0 для выхода полуфабрикатов.

2. **Исправление аналитического дневника `UserNutritionModal`:**
   * Обеспечить корректное извлечение КБЖУ из заказанных блюд и их техкарт.

3. **Исправление сквозного списания сырья в `CheckoutModal` и `StockService`:**
   * Подключить списание сырья со склада при B2C заказах.
   * Синхронизировать `currentStock` и `stockQty` во всех складских операциях (`ReceiptModal`, `WriteOffModal`, `StockService`).

4. **Исправление списания корп. баланса в `PosPaymentModal`:**
   * Добавить списание средств с баланса организации при оплате по корпоративному счету.

5. **Исправление финансового отчета P&L в `FinanceService`:**
   * Обновить фильтры корпоративных заявок по всей цепочке актуальных статусов.
