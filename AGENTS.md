# ПРАВИЛА РАЗРАБОТКИ И ВЕДЕНИЯ ПРОЕКТА

## 1. Стек и совместимость с GitHub Pages
* **Архитектурный принцип:** Приложение должно быть полностью статическим (Client-Side Only), чтобы без серверов запускаться и полноценно функционировать на **GitHub Pages**.
* **Технологический стек:**
  * **HTML5:** Семантическая разметка, чистая структура, поддержка a11y (WCAG 2.1 AA).
  * **CSS3:** Vanilla CSS, использование CSS Custom Properties (дизайн-токены из документа `Дизайн и Цветовая Политика.md`). Никаких тяжелых CSS-фреймворков без прямой необходимости.
  * **JavaScript:** Современный модульный Vanilla JS (ES Modules). Отсутствие обязательного Node.js бэкенда для работы UI.
  * **Хранение данных:** Клиентские хранилища (`localStorage`, `IndexedDB`) с возможностью экспорта/импорта JSON для симуляции персистентности и многоролевых аккаунтов.
  * **Навигация:** Hash-based роутинг (`#/showcase`, `#/pos`, `#/business`, `#/admin`, `#/orders`) или SPA на чистом JS для бесшовной работы на GitHub Pages без проблем с 404 на перезагрузках.

## 2. Дизайн и темизация
* **5 равноправных тем:** `fresh`, `appetite`, `neo-dark`, `corporate`, `premium`.
* **100% токенизация:** Запрещено жестко зашивать HEX-значения цветов в компонентах. Использовать только токены `var(--color-primary)`, `var(--color-accent)`, `var(--color-bg)`, `var(--color-surface)` и т.д.
* **Отсутствие FOUC:** Инициализация темы через inline-скрипт перед рендером DOM.
* **Доступность (WCAG 2.1 AA):** Контраст основного текста не менее 4.5:1, UI-элементов не менее 3:1.

## 3. Регламент ведения истории (.artifacts) и трекера задач
В корне проекта создана папка `.artifacts/` с тремя подпапками:
1. `.artifacts/Запрос/` — сохранение и фиксация каждого запроса и требований пользователя.
2. `.artifacts/Планы/` — сохранение планов реализации, архитектурных решений, схем и декомпозиций задач.
3. `.artifacts/Выполнено/` — подробный отчет о проделанной работе, внесенных изменениях, созданных компонентах и результатах проверки.

### Формат именования файлов истории (СТРОГО ОБЯЗАТЕЛЬНО):
Имя каждого `.md` файла в папках `.artifacts/` формируется строго по шаблону:
```text
Номер - краткое название - дата и время.md
```
* **Номер:** Трехзначный порядковый номер с ведущими нулями (`001`, `002`, `003`...).
* **Название:** Краткая суть задачи/запроса на русском языке.
* **Дата и время:** Формат `YYYY-MM-DD_HH-mm` (например, `2026-08-18_10-05`).
