# Дизайн - Техническое задание
## Цветовая политика и система темизации платформы для общепита

| Параметр | Значение |
|---|---|
| Версия документа | 1.0 |
| Статус | Черновик на согласование |
| Связанные документы | Функциональное описание платформы (B2B/B2C) |
| Область применения | Веб-приложение, мобильные приложения (iOS/Android), POS-терминал |

---

## 1. Общие сведения и цели

### 1.1. Назначение документа
Документ определяет цветовую политику платформы, состав из **пяти визуальных тем**, правила их одновременного сосуществования и механизм пользовательского переключения.

### 1.2. Цели
- **Ц-1.** Предоставить всем пользователям возможность выбирать одну из 5 цветовых тем оформления интерфейса.
- **Ц-2.** Обеспечить мгновенное переключение темы без перезагрузки страницы/экрана.
- **Ц-3.** Синхронизировать выбранную тему между всеми устройствами пользователя через его профиль.
- **Ц-4.** Обеспечить единый подход к цвету через систему дизайн-токенов, исключающий «жёстко зашитые» цвета в компонентах.
- **Ц-5.** Гарантировать доступность (WCAG 2.1 AA) во всех пяти темах.

### 1.3. Ключевой принцип
> **Все 5 тем существуют одновременно и равноправно.** Интерфейс строится на семантических цветовых токенах, которые подменяются при смене темы. Ни один компонент не содержит фиксированных HEX-значений цвета — только ссылки на токены.

## 2. Термины и сокращения

| Термин | Определение |
|---|---|
| **Тема (Theme)** | Именованный набор цветовых токенов, определяющий внешний вид интерфейса |
| **Дизайн-токен** | Именованная переменная, хранящая значение цвета (или иного свойства) |
| **Примитивный токен** | Сырое значение цвета (палитра), например `green-500` |
| **Семантический токен** | Токен с обозначением роли цвета, например `color-primary`, `color-bg` |
| **Активная тема** | Тема, применённая к интерфейсу в текущий момент |
| **Дефолтная тема** | Тема, применяемая при отсутствии пользовательского выбора |
| **WCAG** | Рекомендации по доступности веб-контента |

---

## 3. Объект темизации и границы

### 3.1. Что меняется при смене темы
- Цвета фонов, поверхностей, текста, границ.
- Цвета интерактивных элементов (кнопки, ссылки, активные состояния).
- Цвета навигации, иконок (где применимо).
- Оттенок теней и оверлеев.
- Тайлы карты (светлые/тёмные).

### 3.2. Что НЕ меняется при смене темы (константы)
- Типографика (шрифты, размеры, межстрочные интервалы).
- Геометрия: скругления, отступы, сетка.
- Фотографии блюд и пользовательский контент.
- Смысловая семантика статусных цветов (успех/ошибка/предупреждение).

## 4. Состав тем

Платформа включает **5 тем**. Каждая тема идентифицируется системным ключом.

| № | Название | Ключ темы | Характер | Рекомендуемый сегмент |
|---|---|---|---|---|
| 1 | Свежий рынок | `fresh` | Свежесть, польза | B2C-витрина, столовые, кафе, ЗОЖ |
| 2 | Тёплый аппетит | `appetite` | Аппетит, энергия | Доставка еды, стрит-фуд, фуд-маркетплейс |
| 3 | Нео-дарк | `neo-dark` | Технологичность, тёмный UI | POS-терминал, бизнес-кабинет, дашборды |
| 4 | Корпоративный баланс | `corporate` | Доверие, B2B | Организации-заказчики, финансовый учёт, Админ |
| 5 | Гастро-премиум | `premium` | Премиальность, эстетика | Рестораны, кейтеринг, банкеты |

## 6. Статусные цвета и визуализация данных

### 6.1. Статусные цвета
Статусные цвета несут смысловую нагрузку и **не подменяются** темой радикально — допускается лишь адаптация оттенка под светлый/тёмный фон для сохранения контраста.

| Токен | Семантика | Светлые темы | Тёмная тема (`neo-dark`) |
|---|---|---|---|
| `--color-success` | Успех, готово, принято | `#1F9D55` | `#3DDC84` |
| `--color-success-bg` | Фон успеха | `#E6F5EC` | `#16321F` |
| `--color-warning` | Предупреждение, в работе | `#D98E04` | `#FFC94D` |
| `--color-warning-bg` | Фон предупреждения | `#FCF3DE` | `#3A2E12` |
| `--color-error` | Ошибка, отменено, стоп-лист | `#DC3545` | `#FF6B6B` |
| `--color-error-bg` | Фон ошибки | `#FBE7E9` | `#3A1A1C` |
| `--color-info` | Информация, черновик | `#2E7CD6` | `#6FB3FF` |
| `--color-info-bg` | Фон информации | `#E7F1FC` | `#14283D` |

**Правило С-1.** Запрещено использовать статусные цвета в декоративных целях. Красный — только для ошибок/отмены, зелёный — только для успеха.

### 6.2. Палитра для графиков (data-viz)
Единый категориальный набор из 8 цветов для аналитики (по категориям блюд, общепитам, сотрудникам и т. д.):

| 1 | `#2E7CD6` | Серия A |
| 2 | `#1F9D55` | Серия B |
| 3 | `#E8630A` | Серия C |
| 4 | `#8A4FC0` | Серия D |
| 5 | `#D64560` | Серия E |
| 6 | `#12A5A0` | Серия F |
| 7 | `#B58900` | Серия G |

**Правило D-1.** В тёмной теме (`neo-dark`) яркость data-viz цветов повышается на ~10–15% для читаемости (определяется дизайн-системой как альтернативный набор).

## 7. Механизм выбора и переключения темы

### 7.1. Точки входа для переключения
- **ТВ-1.** Иконка-палитра в шапке приложения (веб и мобильные) — открывает панель быстрого выбора темы.
- **ТВ-2.** Раздел «Настройки → Внешний вид» в профиле пользователя.
- **ТВ-3.** Экран онбординга при первом входе — предложение выбрать тему (можно пропустить).

### 7.2. Панель выбора темы
Панель отображает все 5 тем в виде превью-карточек:
- Миниатюра с образцом цветов (primary + accent + фон).
- Название темы и её ключ.
- Отметка активной темы (галочка/рамка).
- Краткое описание характера темы.

**Требование П-1.** Применение темы происходит мгновенно по клику, без перезагрузки и без дополнительного подтверждения.
**Требование П-2.** Выбор сопровождается плавным переходом цветов длительностью 200–300 мс.
**Требование П-3.** Выбранная тема автоматически сохраняется в профиле пользователя.

### 7.3. Пользовательские сценарии (User Stories)

| ID | Сценарий |
|---|---|
| US-1 | Как клиент, я хочу выбрать тему «Тёплый аппетит», чтобы витрина выглядела аппетитно, и чтобы выбор сохранился при следующем входе |
| US-2 | Как кассир общепита, я хочу переключиться на «Нео-дарк» в POS-терминале, чтобы снизить усталость глаз в течение смены |
| US-3 | Как владелец сети, я хочу задать тему «Корпоративный баланс» как дефолт для кабинетов моих сотрудников |
| US-4 | Как новый пользователь без настроек, я вижу дефолтную тему и могу сменить её в любой момент |
| US-5 | Как пользователь, вошедший с нового устройства, я автоматически получаю свою сохранённую тему из профиля |

## 8. Правила применения по ролям и разделам

### 8.1. Рекомендуемые дефолты по ролям
Дефолт применяется **только при отсутствии личного выбора** пользователя.

| Роль | Дефолтная тема | Обоснование |
|---|---|---|
| Клиент (физ. лицо) | `fresh` | Универсальная, свежая, B2C |
| Общепит — кабинет | `corporate` | Доверие, учёт, финансы |
| Общепит — POS | `neo-dark` | Долгая работа, снижение усталости |
| Организация-заказчик | `corporate` | B2B-заявки, отчётность |
| Администратор | `corporate` | Рабочий инструмент |

### 8.2. Приоритет применения темы
Порядок определения активной темы (от высшего к низшему):

1. **Личный выбор пользователя** (сохранён в профиле).
2. **Дефолт по роли** текущего контекста (если личный выбор не сделан).
3. **Дефолт платформы**, задаваемый администратором (глобальная настройка).
4. **Системный запасной вариант** — тема `fresh`.

**Требование Р-1.** Личный выбор пользователя всегда имеет наивысший приоритет и перекрывает любые дефолты.

### 8.3. Опциональная возможность (Фаза 2)
- **О-1.** Администратор платформы может задать дефолтную тему для публичной Витрины.
- **О-2.** Владелец общепита может задать корпоративную тему для кабинетов своей организации.
- **О-3.** Пользователь может установить разные темы для разных разделов (Витрина / Кабинет / POS) — сохраняется как карта `раздел → тема`.

## 9. Хранение и синхронизация настроек

### 9.1. Модель данных
В профиль пользователя добавляется блок настроек внешнего вида:

```json
{
  "appearance": {
    "theme": "fresh",
    "themeBySection": {
      "showcase": null,
      "business": "corporate",
      "pos": "neo-dark"
    },
    "updatedAt": "2025-01-01T12:00:00Z"
  }
}
```

### 9.2. Правила хранения
- **Х-1.** Выбранная тема сохраняется на стороне сервера в профиле пользователя и синхронизируется между устройствами.
- **Х-2.** Для неавторизованных посетителей выбор хранится локально (`localStorage` / `SecureStorage` мобильного приложения) и переносится в профиль после регистрации.
- **Х-3.** Значение темы валидируется: принимаются только ключи из разрешённого набора `fresh | appetite | neo-dark | corporate | premium`. Неизвестное значение трактуется как дефолт.
- **Х-4.** При смене темы клиент отправляет `PATCH`-запрос на сохранение предпочтения; применение на экране не зависит от ответа сервера (оптимистичное обновление).

## 10. Требования к реализации

### 10.1. Архитектура темизации
- **ТР-1.** Все цвета задаются через CSS Custom Properties, привязанные к атрибуту темы на корневом элементе: `html[data-theme="fresh"]`, `html[data-theme="appetite"]` и т. д.
- **ТР-2.** В компонентах используются **только семантические токены** (`var(--color-primary)` и т. п.). Использование HEX-значений напрямую в компонентах запрещено (контролируется линтером).
- **ТР-3.** Определение тем выносится в единый файл тем (например, `themes.css` или дизайн-токены в JSON с генерацией CSS).
- **ТР-4.** Мобильные приложения реализуют эквивалентный механизм через свои системы темизации (ThemeProvider / appearance assets), сохраняя те же значения токенов.

### 10.2. Применение темы при загрузке
- **ТР-5.** Тема применяется **до первой отрисовки** интерфейса (inline-скрипт в `<head>` читает сохранённое значение и выставляет `data-theme`), чтобы избежать «мигания» дефолтной темы (FOUC).
- **ТР-6.** Если сохранённая тема не может быть определена, применяется дефолт по приоритетам из п. 8.2.

### 10.3. Переход и стабильность
- **ТР-7.** Смена темы занимает не более 100 мс до визуального применения.
- **ТР-8.** Переход сопровождается анимацией `transition: background-color .25s ease, color .25s ease, border-color .25s ease`. Анимация отключается при `prefers-reduced-motion`.
- **ТР-9.** Смена темы не вызывает перезагрузку страницы и не сбрасывает состояние форм/корзины.

### 10.4. Адаптация контента
- **ТР-10.** Иконки используют `currentColor` или адаптивные SVG, чтобы корректно перекрашиваться.
- **ТР-11.** Фотографии блюд и пользовательские изображения не тонируются и не меняются при смене темы.
- **ТР-12.** Компоненты карт (Яндекс/Google/2GIS) используют светлые тайлы в светлых темах и тёмные — в `neo-dark`.
- **ТР-13.** Графики и диаграммы используют data-viz палитру (п. 6.2) с учётом светлой/тёмной основы темы.

---

## 11. Доступность (a11y)

- **А-1.** Контраст основного текста к фону — не ниже **4.5:1** (WCAG 2.1 AA) во всех пяти темах.
- **А-2.** Контраст крупного текста и элементов интерфейса — не ниже **3:1**.
- **А-3.** Каждая из 5 тем проходит автоматизированную проверку контраста до включения в релиз.
- **А-4.** Информация не передаётся только цветом: статусы дублируются текстом или иконкой.
- **А-5.** Фокус-индикаторы клавиатурной навигации видны во всех темах (контрастная обводка).
- **А-6.** Состояния hover / active / disabled различимы во всех темах.

## 12. Производительность и совместимость

- **ПФ-1.** Поддержка всех современных браузеров (последние 2 мажорные версии Chrome, Safari, Firefox, Edge).
- **ПФ-2.** Размер файлов тем не должен существенно увеличивать бандл; определения тем кэшируются.
- **ПФ-3.** При недоступности сохранённой темы (ошибка сети, повреждённые данные) интерфейс загружается с дефолтной темой без ошибок.
- **ПФ-4.** Поддержка печати: принт-стили используют светлую читаемую палитру независимо от активной темы.

---

## 13. Ограничения использования цвета

- **ОГ-1.** `--color-accent` применяется только для ключевых целевых действий (оформить заказ, создать заявку, оплатить). Запрещено массовое использование акцента.
- **ОГ-2.** `--color-error` используется исключительно для ошибок и отмен; `--color-success` — только для успешных состояний.
- **ОГ-3.** Запрещено вводить новые цвета вне дизайн-токенов без согласования с дизайн-системой.
- **ОГ-4.** В тёмной теме не используются чистый чёрный фон и чисто белый текст без смягчения (применяются значения из токенов темы).

## 14. Критерии приёмки

|---|---|
